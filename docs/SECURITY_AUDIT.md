# Breeze 보안 점검 (신규 기능 + 기존 취약점)

## 2026-10-22 온프레미스 차세대 기능 점검

### 1) AI 상담 일지
- ✅ 원문은 학교 SQLite에만 저장하며, 작성자와 관리자만 조회할 수 있습니다. 학생 계정은 API 단계에서 차단됩니다.
- ✅ 외부 AI로 보내기 전 주민등록번호·휴대폰·카드번호를 서버에서 마스킹하며, 마스킹 건수는 클라이언트 값이 아니라 서버에서 재계산합니다.
- ✅ AI 호출은 분당 제한(`aiLimiter`)과 15초 타임아웃을 적용하고, 실패 시 로컬 분류로 대체합니다.
- ⚠️ 외부 AI 키가 설정된 경우 생성형 AI 사업자에게 마스킹된 상담 문장이 전송됩니다. 학교 개인정보 영향평가에서 이 사실을 고지하고, 가능하면 교내망 전용 모델 또는 비활성 정책을 선택하십시오.

### 2) 간이 전자결재
- ✅ 승인·반려는 `ADMIN`만 가능하며, 자기 결재 승인은 서버에서 차단합니다.
- ✅ 승인 시 결재 ID·승인자·서명·상태·시각을 조합한 SHA-256 해시를 보관합니다. 본문은 감사 로그에 저장하지 않습니다.
- ✅ 결재 생성·처리·취소는 append-only 감사 기록과 서버 텍스트 활동 로그에 남습니다.
- ⚠️ 전자서명은 계정 이름을 기반으로 한 간이 서명이며, 법적 효력이 필요한 문서에는 공동인증서·전자문서 서명을 별도로 적용하십시오.

### 3) 실시간 협업 보드
- ✅ 좌표·크기·색·문자 수를 서버에서 강제하고, 보드 JSON 120KB·항목 240개 상한을 적용합니다.
- ✅ version 낙관적 잠금으로 동시 저장 덮어쓰기를 방지하고, 소켓 업데이트에 40ms 스로틀을 적용합니다.
- ✅ 학생 계정은 REST·소켓 모두 차단하며, 삭제는 작성자 또는 관리자만 가능합니다.
- ⚠️ 교사 간 공동 편집은 의도된 기능이므로, 민감한 학생 명단을 보드에 입력하지 않도록 학교 정책을 안내하십시오.

### 4) 공개 웹 스마트 배너
- ✅ `titleHtml`·`metaHtml`·`data-action`을 `innerHTML`에 그대로 넣던 경로를 제거하고, `esc()` 및 action/class 화이트리스트를 적용했습니다.
- ✅ 외부 링크는 `http(s)`만 확인 후 이동하며, `mailto:`·`tel:` 외 스킴은 차단합니다.

### 5) 이용권 주문·결제
- ✅ 금액은 서버의 요금제 정의로만 계산하며, 클라이언트가 보낸 금액을 신뢰하지 않습니다.
- ✅ `licenseOrders`는 Functions의 Admin SDK만 생성·수정할 수 있고, 읽기는 구매자 본인과 총관리자로 제한합니다.
- ✅ 멱등 키를 해시한 주문 ID와 Firestore 트랜잭션으로 재시도 중복 주문을 막고, 이용권 발급은 이미 결제된 주문이면 기존 코드를 반환합니다.
- ✅ 웹훅은 `x-breeze-signature` HMAC-SHA256과 주문 금액 일치를 모두 확인한 뒤 발급합니다.
- ✅ 인증코드는 주문 문서에 저장하지 않고 `licenses` 문서에만 두며, 결제 확인서에는 인증코드를 표시하지 않습니다.
- ⚠️ `PAYMENT_MODE=sandbox`는 실제 청구 없이 이용권을 발급하므로 운영 환경에서 사용하면 안 됩니다. 기본값은 `manual`입니다.
- ⚠️ 실제 카드 승인·취소·부분 환불 웹훅은 결제대행사 계약 후 별도 검증이 필요합니다. 현재 `live` 경로는 HTTPS 결제 창 URL과 `payment.paid` 웹훅만 처리합니다.

### 6) 남은 라이선스 구조 개선 (사용자 확인 필요)
- ⚠️ 현재 HMAC 기반 라이선스와 `license.secret` 파일, loopback `/api/admin/secret` 경로가 남아 있습니다. Ed25519 공개키 검증으로 전환하고 loopback 비밀 노출 경로를 제거하려면 벤더 키·기존 발급 키 마이그레이션 계획이 필요합니다. 운영 키를 삭제하기 전에 반드시 사용자 확인을 받아야 합니다.

## 기존 점검 (2026-09-30)

점검일: 2026-09-30 / 대상: desktop-native + public memo-hybrid + firestore.rules / 기준: OWASP Top 10 + K-ISMS-P

## 신규 기능 보안 상태

### 1) Pre-Send On-Device DLP — 양호 (조건부)
- ✅ 차단 우선: `verdict=block` 시 클라우드 `add()` 호출 자체를 안 함 (memo-hybrid.js `sendMemo`).
- ✅ 평문 미저장: 감사로그는 AES-256-GCM 암호화, 샘플은 `[redacted]`.
- ⚠️ 우회 가능: 렌더러 변조 시 DLP 스킵 가능 → 서버사이드 2차 검증(Firestore Rules + Functions) 필수. 현재 Rules는 길이만 검사하므로 Functions에서 정규식 재검사를 권장.
- ⚠️ 모델 탈취: ONNX 파일이 번들에 평문이면 추출 가능 → 모델 난독화/무결성 체크 필요.

### 2) P2P Serverless — 주의
- ✅ LAN 한정: 브로드캐스트가 교내망 밖으로 안 나감 (255.255.255.255 + 서브넷).
- ⚠️ 평문 전송: 현재 TCP 프레임이 평문 JSON → 동일 LAN에서 스니핑 가능. **TLS-PSK 또는 NaCl box로 암호화 필수** (사전공유키를 학교코드로 파생).
- ⚠️ 스푸핑: `displayName` 위조 가능 → `nodeId = pubkey 해시` + 서명 검증으로 교체 권장.

### 3) RAM 미리보기 — 양호
- ✅ 디스크 기록 ZERO: `Buffer.fill(0)` 후 해제, tmpdir 미사용 (스모크 테스트 확인).
- ⚠️ 스왑/덤프: OS 페이징 시 RAM이 디스크로 스왑될 수 있음 → 민감문서는 미리보기 후 `destroyPreview` 즉시 호출, 최대 64MB 상한 유지.

### 4) AutoPurge — 양호
- ✅ 수신파일만 대상, 30일/TTL + 3GB 상한. `recv-cache` 외부 경로는 건드리지 않음.
- ⚠️ TOCTOU: 삭제 중 앱 종료 시 잔류 가능 → 시작 20초 후 1회 재실행으로 보완됨.

### 5) USB/캡처가드 — 부분적 방어
- ✅ 탐지+감사로그는 동작. `setContentProtection(true)`로 화면공유/스크린샷 1차 방어.
- ⚠️ 완전 차단 불가: 앱 레벨에서는 USB 복사 차단·커널 캡처 차단이 안 됨 → DLP 정책상 “경고+로그”로 명시하고, 드라이버(커널) 제품을 별도로 고지해야 함. 허위 “100% 차단” 문구 금지.

## 기존 코드에서 발견된 취약점 (수정 반영)

1. **[수정] preload allowlist 없음 → allowlist 추가**: 기존 `edutalkDesktop`이 invoke 채널을 무제한 노출하지는 않았지만, 신규 채널 추가 시 우회 우려 → `ALLOWED_INVOKE/ALLOWED_ON` + `safeInvoke/safeOn` 적용.
2. **[수정] Firestore `memos` 컬렉션 없음 → Rules 추가**: 제목/본문 길이 제한, `fromUid==auth.uid` 강제, `delete:false`, 댓글은 2000자·생성만 허용.
3. **[수정] 클라이언트 웹 앱 식별자 분리**: 공개 식별자는 저장소에서 빼고 배포 시 `firebase-config.js`·빌드 환경 변수로 주입합니다. 콘솔에서 HTTP referrer 제한과 App Check를 함께 켜야 합니다. 서비스 계정 키는 어느 클라이언트에도 두지 않습니다.
4. **[잔존] XSS**: `app.js` 1MB에 innerHTML 다수 사용 → 신규 코드(`memo-hybrid.js`)는 `esc()` + `textContent` 사용. 기존 코드는 DOMPurify 도입 권장.
5. **[해결] 레거시 데스크톱 런타임 제거**: 새 앱은 `edutalk-core`의 데스크톱 런타임과 좁은 권한 모델을 사용합니다. 외부 열기는 http/https/mailto/tel만 허용합니다.
6. **[완료] CSP**: 데스크톱 앱 설정에 CSP를 추가했습니다. 레거시 웹 자산은 더 이상 배포 경로에 두지 않습니다.
7. **[권장] 자동업데이트 서명**: NSIS oneClick 배포 시 업데이트 파일 위변조 대비 `publisherName +签名` 설정 필요.

## 2026-11-10 학생 위협 모델·온프레미스 경로 점검

점검 범위: 학생이 개인 노트북에 교사용 클라이언트를 설치한 뒤 교내 서버를 공격하는 경우, 매크로·연타로 서버를 마비시키는 경우, 학생 계정으로 교사 전용 데이터에 접근하는 경우를 포함합니다.

### 1) 인증·세션
- ✅ API 토큰은 `Authorization: Bearer` 헤더로만 받습니다. 쿼리 문자열·요청 본문 토큰 폴백은 제거하여 URL 로그·브라우저 기록을 통한 토큰 유출 경로를 차단했습니다.
- ✅ 로그인 시도는 IP당 분당 12회로 제한하며, 초기 관리자 비밀번호는 8자 이상·128자 이하만 허용합니다.
- ✅ 초기 설정 API는 서버 PC 본체(loopback 또는 서버 자신의 교내 IP)에서만 호출할 수 있고, `trust proxy`를 끄어 `X-Forwarded-For` 위조로 loopback 판정을 우회할 수 없습니다.

### 2) 학생 계정의 교사 기능 접근 차단
- ✅ 부서·사용자·채팅방·메시지·읽음 명단·할 일·양식함·업데이트 중계 경로에 `needStaff`를 적용하여 학생 계정의 호출을 서버 단계에서 거부합니다.
- ✅ 채팅방 생성·초대·삭제·나가기에서 학생 계정을 멤버로 추가하지 않으며, 기존 멤버 목록에 학생이 섞여 있어도 초대 대상에서 제외합니다.
- ✅ 소켓 메시지 전송·방 입장·읽음·투표·상태 변경·화이트보드 입장/퇴장에 소켓별 속도 제한을 적용했습니다.

### 3) 파일·첨부 접근 제어
- ✅ 파일 다운로드는 업로더 본인, 해당 쪽지의 발신자·수신자, 해당 채팅방 참여자로 제한합니다. 파일 번호를 알아내는 것만으로 학생 사진·첨부를 내려받는 IDOR를 차단했습니다.
- ✅ 쪽지 첨부는 발신자가 직접 업로드한 파일 중 아직 쪽지에 붙지 않은 파일만 허용합니다. 타인의 파일을 첨부하는 경로를 차단했습니다.
- ✅ 업로드·학생 미디어·양식 등록에는 분당 8회의 업로드 제한을 적용했습니다.

### 4) 업데이트·설정
- ✅ 업데이트 중계·임차권·반납 API는 교직원 전용으로 제한하여 학생 계정이 위조 설치본을 배포하지 못하게 했습니다.
- ✅ 데스크톱 CSP에서 외부 CDN(`cdn.jsdelivr.net`) 허용을 제거하여 앱이 자체 번들·폰트만 불러오도록 축소했습니다.
- ⚠️ 업데이트 중계 매니페스트에는 벤더 전자서명이 없습니다. 교직원 계정이 탈취될 경우 위조 설치본 배포가 가능하므로, 운영 전 Ed25519 서명 검증 또는 관리자 전용 배포 정책을 적용하십시오.
- ⚠️ 교내 구간은 HTTP 평문 통신입니다. 학생이 같은 LAN에서 트래픽을 스니핑할 수 있으므로, 장기적으로 TLS 적용과 HSTS·인증서 배포 계획을 수립하십시오.

### 6) 잔여 위험
- ⚠️ 레이트리밋은 서버 메모리 기반이므로 서버 재시작 시 초기화됩니다. 다중 서버 구성이 필요한 경우 외부 저장소 기반 제한으로 교체하십시오.
- ⚠️ 교사 계정 탈취를 전제로 한 위협은 완전히 차단되지 않습니다. 관리자 계정은 별도 강한 비밀번호·주기적 교체·감사 로그 모니터링을 적용하십시오.
- ⚠️ 학생용 웹은 브라우저에서 실행되므로 클라이언트 측 조작이 가능합니다. 권한 판단은 반드시 서버에서 수행하며, 클라이언트 상태를 신뢰하지 않습니다.

- 데스크톱 전용 기능은 “로컬 우선 + 클라우드 미송신” 원칙을 지켜 DLP/RAM/Purge는 양호합니다.
